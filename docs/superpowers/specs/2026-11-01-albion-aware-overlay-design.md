# AlbionAware 战况悬浮窗 — 设计文档

- 日期：2026-11-01
- 状态：待用户审阅

## 1. 目标

给 Albion Online 玩家一个**常驻游戏画面上、几乎不占视野**的小窗：只显示当前区域内的**非队友玩家**，一眼可见的只有**武器图标 + IP**；有新非队友出现时闪红边框。点击某一行可展开该玩家详情（名字、公会、装备、药水、食物等）。

非目标（Out of Scope）：
- 不显示队友、不显示自己
- 不做玩家距离/方向（官方已加密坐标，技术上不可得）
- 不做地图、不做资源/传送门（已另案放弃）
- 不支持 Linux / macOS（首发仅 Windows 10/11）
- 不注入游戏进程、不读写游戏内存、不修改游戏文件

## 2. 架构

单进程 Python 桌面程序，直连 OpenRadar 已公开的 WebSocket。

```
游戏 UDP 5056
   └─ OpenRadar（打包附带，抓包 + 解析 + WS 广播）
        └─ ws://localhost:5001/ws
             └─ AlbionAware 悬浮窗（本产品）
                  ├─ 事件解析层：玩家/队伍/换图/离开
                  ├─ 状态层：玩家表、队友名单、配置
                  ├─ 界面层：68px 窄窗 + 详情面板 + 闪烁
                  └─ 系统层：置顶/穿透/热键/托盘
```

**关键点**：悬浮窗直接消费原始 WS 事件，**不依赖雷达前端**，因此不受雷达 Web UI 的过滤器与 localStorage 开关影响（这是此前“0 players”问题的根源）。

### 2.1 组件划分

| 组件 | 职责 | 依赖 |
|---|---|---|
| `radar_client.py` | 连接 WS、断线重连、把消息分发给解析层 | websocket-client |
| `event_parser.py` | 事件码 → 领域事件（玩家出现/更新/离开/队伍变更/换图/装备） | 物品库 |
| `player_store.py` | 玩家表、去重、超时清理、排序、过滤（自己/队友） | — |
| `party.py` | 队友名单（自动事件 + 手动），持久化 | — |
| `icons.py` | 武器图标获取与本地缓存（在线渲染 → 缓存 → 占位图） | Pillow、requests |
| `overlay.py` | 无边框置顶窗口、行渲染、闪烁、点击、拖动 | tkinter、Pillow |
| `win32_ext.py` | 鼠标穿透、全局热键、托盘 | ctypes / pystray |
| `config.py` | 配置文件读写、i18n 语言选择 | — |
| `launcher.py` | 环境检测、启动雷达、首启向导、诊断 | OpenRadar HTTP API |
| `i18n.py` | 文案加载（zh-CN / en） | lang/*.json |

## 3. 数据与判定

### 3.1 输入事件（基于实测验证）

| 用途 | 事件 |
|---|---|
| 玩家出现/更新（昵称、装备、血量、公会） | NewCharacter = 29；同一玩家后续属性/血量事件只更新字段，不重复触发闪烁 |
| 玩家离开 | Leave（参数 252 == 1，参数 0 = 离开者 id） |
| 换图 | 响应 op 41（参数 0 = 新区 ID）；同时清空玩家表 |
| 队伍成员变化 | 231 / 233 / 234 / 235 / 236 |
| 自身位置（可选，仅用于“同区”确认） | 请求 op 22 |

事件码与字段以源码仓库 `web/scripts/**` 与实测日志为准；解析层对未知事件静默忽略，不影响主体。

### 3.2 领域规则

| 规则 | 处理 |
|---|---|
| 自己 | 配置中的昵称匹配则排除；昵称为空时首启向导提醒填写 |
| 队友 | 雷达队伍事件自动加入名单；点击详情“标记队友”手动加入；名单持久化 |
| 非队友 | 同区玩家中，非自己且不在队友名单 → 进列表 |
| 离开 | 收到离开事件立即移除；60 秒无更新也移除（超时可配） |
| 换图 | 清空全部玩家与选中状态 |
| 排序 | 默认“最新出现优先”；可切换“IP 从高到低” |

## 4. 界面

### 4.1 主窗

- 无边框、圆角、背景 85% 黑色；**宽 68px**、行高 26px、上下内边距 4px
- 每行：武器图标 22×22 + 右侧 4 位 IP 数字
- IP 颜色分级：<800 灰白 / 800–1000 黄 / >1000 橙红
- 默认显示 6 行；超出时第 7 行显示 `+N`，点击展开全部
- 默认位置：屏幕右侧贴边 8px，垂直约 1/3 高度；`Ctrl` + 拖动可移动，位置持久化

```
┌────────┐
│ 🗡 1250 │
│ 🏹 1080 │
│ 🛡  920 │
│  +3    │
└────────┘
```

### 4.2 详情面板

点击行 → 面板在**主窗左侧**展开（宽 220px，主窗位置不变）：

- 名字、公会、联盟
- IP、首次发现时间、最近更新时间
- 装备 8 格图标（主手/副手/头/胸/鞋/披风/坐骑/背包），悬停显示英文物品名
- 药水、食物（协议提供则显示）
- 技能（协议提供则显示；拿不到就整块隐藏）
- 操作：`标记队友`、`复制名字`

缺失数据一律隐藏对应区块，不显示“未知”占位。

### 4.3 闪烁

- 触发条件：出现**新的**非队友
- 表现：窗口四周 2px 红色描边，400ms × 5 次（约 2 秒）后自动消失
- 不改变内容布局，不遮挡文字

### 4.4 热键

| 键 | 行为 |
|---|---|
| `F10` | 切换 可点击 / 鼠标穿透 |
| `F9` | 将当前选中行标记为队友 |
| `F8` | 显示 / 隐藏悬浮窗 |

默认热键可在配置文件中修改（游戏本身可能占用 F8/F9/F10，冲突时玩家自行改键）。

## 5. 交互与系统行为

- 默认**可点击**（为了点击看详情）；`F10` 切鼠标穿透后完全不干扰游戏操作
- 托盘常驻：右键菜单 = 显示/隐藏、切换穿透、重置位置、反馈问题、关于、退出
- 窗口始终置顶（`WS_EX_TOPMOST`），不抢焦点（`WS_EX_NOACTIVATE`）

## 6. 启动器与环境检测（傻瓜化）

安装后玩家只需双击桌面图标。启动器按序执行：

| 步骤 | 检测方式 | 处理 |
|---|---|---|
| Npcap 是否安装 | `sc query npcap` 返回 1060 | 静默安装官方包（`/S`）；许可不允许内置时自动下载官方安装包并执行，或打开下载页 |
| Npcap 是否运行 | 服务状态非 RUNNING | `sc start npcap`（需管理员） |
| 选网卡 | 调雷达 `/api/network/refresh` 与 `/api/network/interfaces` | **默认全选所有网卡**（实测物理网卡 + 虚拟网卡可同时抓） |
| 雷达是否就绪 | 轮询 `localhost:5001/api/network/state` | 未就绪则等待并重试，超时给提示 |
| 零流量 | 连续 60 秒 0 个游戏包 | 弹出诊断向导（见 6.1） |

权限：启动器与安装器带 `requireAdministrator`；悬浮窗**不提权**。

### 6.1 诊断向导（零流量时）

1. 自动诊断报告：各网卡收包数、雷达版本、检测到的加速器进程、是否有游戏进程
2. 一键“刷新并全选网卡”（应对加速器刚切换模式后新出现的虚拟网卡）
3. 分场景指引按钮：
   - 我用加速器 → 按检测到的品牌给对应步骤（雷神→模式 3；迅游/奇游/UU→路由/虚拟网卡模式；ExitLag→必须改 Route 模式，其默认 WFP 模式在 NDIS 之上，任何抓包工具都看不到）
   - 我没用加速器 → 检查防火墙/安全软件、确认游戏进程
   - 不确定 → 通用三步骤
4. “复制诊断信息并打开反馈页”

## 8. 多语言

- 文案抽离为 `lang/zh-CN.json`、`lang/en.json`，启动跟随系统语言，托盘可切换
- **默认规则**：Windows 系统语言为 `zh-CN/zh-TW/zh-HK` → 中文；其余一律 **English**（国际兜底）
- **切换方式**：① 托盘右键 → `Language / 语言` 子菜单（跟随系统 / 中文 / English），选中后文案热重载、立即生效；② 首启向导第一屏的语言下拉（防止系统识别不准）；③ 配置项 `"language": "auto|zh-CN|en"` 可直接编辑
- 安装器（Inno Setup）安装阶段同样支持语言选择并默认跟随系统
- 首发中英双语，后续可加 pt-BR / ru / es（仅新增 JSON）
- 悬浮窗本体几乎无文案（图标 + IP）；翻译量集中在安装器、向导、托盘、错误提示（约 100 条）
- 详情面板物品名使用官方英文名（`T6_MAIN_SWORD` → `Master's Sword`），不随语言变化

## 10. 错误处理

| 场景 | 处理 |
|---|---|
| WS 断开 | 指数退避重连（1s→2s→4s→…上限 30s），窗口角标显示灰色状态点 |
| 雷达未运行 | 托盘提示 + 状态点变红；启动器负责拉起 |
| 图标下载失败 | 使用本地缓存；仍失败则显示按武器类型区分的占位图标（不显示破图） |
| 物品库缺失 | 详情面板隐藏装备区块，IP 显示为 `-` |
| 配置损坏 | 备份为 `.bak` 并重建默认配置 |
| 未知事件码 | 静默忽略并计数（诊断包里体现） |

## 11. 测试策略

- **解析层单测**：用真实会话事件样本（离线 JSONL）驱动，验证玩家出现/更新/离开/换图/队伍变更到领域事件的映射
- **状态层单测**：去重、超时清理、过滤自己/队友、排序
- **界面冒烟**：脚本注入模拟玩家表，验证行渲染、超员折叠、详情面板、闪烁计时
- **手动集成**：开启雷达 → 进游戏 → 验证真实玩家出现、闪烁、点击详情、标记队友、换图清空
- **环境检测**：模拟 Npcap 未安装/未运行分支（用桩替换命令执行）

## 12. 风险与已知限制

| 风险 | 说明 |
|---|---|
| 玩家坐标加密 | 无法给出距离/方向，只能区分“在同区” |
| 加速器 WFP 模式 | 物理上抓不到包，只能引导改模式 |
| 杀软误报 | 抓包类工具常见；靠开源 + SHA256 + VirusTotal 缓解 |
| 事件码随游戏版本变化 | 游戏更新后需跟随上游雷达升级，解析层按“未知事件忽略”兜底 |
| 雷达为 beta 版本 | 提示玩家随上游更新，版本号在关于窗口展示 |
